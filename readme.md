# forge-go 🛠️🔥

`forge-go` — это производительная, отказоустойчивая и наблюдаемая Enterprise-платформа (каркас) на языке Go. Спроектированная в строгом соответствии с принципами Clean Architecture, Domain-Driven Design (DDD) и SOLID, она предоставляет унифицированный промышленный фундамент для построения Cloud-Native microservices, способных выдерживать Highload-нагрузки.

## 💎 Ключевые архитектурные достоинства

* **Наблюдаемость (Observability):** Сквозной распределенный трейсинг (`RequestID`/`TraceID`) полностью интегрирован на уровне HTTP и gRPC транспортов. Родная поддержка механизмов **Prometheus Exemplars** в гистограммах задержек (Latency) позволяет инженерам в один клик переходить от аномальных спайков на графиках Grafana к точным трассировкам следов в Jaeger/Tempo.
* **Оборонительный дизайн рантайма (DoS/OOM Protection):** Адаптивный контроль ресурсов проактивно защищает оперативную память подов от вредоносных payload и эксплойтов декомпрессии (Zip-бомб) через жесткие ограничения `MaxBytesReader`, внедренные в парсинг JSON и динамическое сжатие потоков (Brotli/Gzip).
* **Отказоустойчивость (Fault Tolerance):** Пулы соединений с СУБД и асинхронные клиенты брокеров очередей (Apache Kafka, AMQP 1.0/Azure Service Bus) реализуют потокобезопасные паттерны **Double-Check Locking**. Восстановление связи при сбоях инфраструктуры вынесено за рамки критических зон блокировок мьютексов с помощью механизмов ленивой инвалидации сессий (`Invalidate`).
* **Детерминированное управление жизненным циклом:** Орикестратор IoC/DI контейнеризации (`BaseApplication` / `container.Runner`) координирует плавный контролируемый останов (**Graceful Shutdown**) с двухбарьерными системами таймаутов, гарантируя доваривание открытых транзакций СУБД и финализацию пачек сообщений брокера перед гашением пода.

## 🏗️ Спецификация структуры (Standard Go Structure)

Платформа строго придерживается общепринятого стандарта **Standard Go Project Layout** в сочетании с жесткой изоляцией слоев.

```text
.
├── api/                    # Контракты API и спецификации
│   ├── proto/              # Схемы gRPC сервисов Protobuf
│   └── rest/               # Генераторы клиентов, HTTP-коллекции и файлы тестирования
├── bin/                    # Скомпилированные бинарные артефакты сборки
├── cmd/                    # Точки входа в архитектуру приложения
│   ├── gen-tz/             # CLI-утилита для кодогенерации скомпилированных констант таймзон
│   └── example-service/    # Точка входа: сборка DI-контейнеров и запуск демонстрационного сервиса
├── configs/                # Документация и руководства по настройке инфраструктуры (брокеры, кэш)
├── deployments/            # Инфраструктурные манифесты (Dockerfile, compose, k8s)
├── docs/                   # Автоматически сгенерированная API документация Swagger UI
├── internal/               # Приватный контур приложения (Инкапсулированная бизнес-логика)
│   ├── app/                # Логика инициализации слоев DI и Graceful Shutdown
│   │   └── container/      # Специфичные для конкретного сервиса DI-контейнеры
│   ├── config/             # Паспорт конфигурации: маппинг YAML/ENV/Flags через Viper
│   ├── domain/             # Сердце системы: чистые доменные сущности, инварианты и агрегаты
│   │   └── mocks/          # Изолированная зона автогенерации моков для бизнес-компонентов
│   ├── facade/             # Границы системы: фасады маршрутизации BLL-границы
│   │   ├── dto/            # Data Transfer Objects (объекты переноса данных)
│   │   └── mapper/         # Изолированные трансляторы структурных преобразований данных
│   ├── usecase/            # Логика приложения: сценарии бизнес-логики Single Responsibility
│   │   └── trace/          # Телеметрия бизнес-логики и трассировка контекстов спанов
│   ├── repository/         # DAL: Адаптеры хранилищ данных (Postgres, Redis, Cache)
│   │   ├── metrics/        # Метрики Prometheus для адаптеров хранилищ
│   │   ├── trace/          # Трейсинг OpenTelemetry для операций с БД
│   │   └── postgres/       # Инфраструктурная реализация SQL для PostgreSQL
│   └── transport/          # Входные сетевые контроллеры доставки (REST / gRPC)
├── migrations/             # Схемы эволюции состояний баз данных (SQL)
│   └── example-service/    # Скрипты миграций базы данных Example Service
├── pkg/                    # Переиспользуемые библиотеки платформы (Ядро фреймворка)
│   ├── api/                # Сгенерированные пакеты клиентов и сетевые интерфейсы
│   ├── app/                # Общие платформенные шаблоны и заготовки приложений
│   ├── auth/               # Единый контур аутентификации и управления токенами безопасности
│   ├── config/             # Базовые чертежи движка конфигурации
│   ├── container/          # Универсальные IoC/DI контейнеры и системные хелперы
│   ├── db/                 # Абстракции SQL-баз данных и менеджеры транзакций
│   │   └── postgres/       # Конкретный адаптер реляционной базы данных для PostgreSQL
│   ├── domain/             # Системные дженерик-модели доменных сущностей и репозиториев
│   ├── errs/               # Centralized типизированная таксономия ошибок Enterprise-уровня
│   ├── helper/             # Высокопроизводительные системные утилиты рантайма
│   ├── infra/              # Движок телеметрии и кэширования
│   │   ├── cache/          # Обертки для работы с локальным и распределенным кэшем
│   │   ├── metrics/        # Кастомные коллекторы Prometheus и интерцепторы метрик
│   │   ├── pubsub/         # Легковесная реализация архитектурного паттерна Pub/Sub
│   │   └── telemetry/      # Обертки для распределенного трейсинга экосистемы OpenTelemetry
│   ├── logger/             # Быстрое структурированное логирование на базе ядра Uber Zap
│   ├── migration/          # Общие абстракции движков миграций данных
│   │   └── goose/          # Промышленная обертка над движком миграций Goose
│   ├── repository/         # Высокопроизводительные Generic CRUD и Owned репозитории
│   │   ├── metrics/        # Компоненты-декораторы для сбора метрик Prometheus
│   │   └── trace/          # Компоненты-декораторы для трейсинга распределенных спанов
│   └── transport/          # Абстрактные сетевые реализации протоколов
│       ├── brokers/        # Универсальная агностичная шина обмена сообщениями
│       │   ├── amqp/       # Описание протокольного слоя AMQP
│       │   │   └── azure/  # Клиентский драйвер Azure Service Bus для AMQP 1.0 (go-amqp)
│       │   └── kafka/      # Драйвер для Apache Kafka с ручным управлением оффсетами
│       ├── grpc/           # Серверы gRPC, параметры KeepAlive и интерцепторы
│       │   └── interceptors/ # Кастомные gRPC перехватчики для Unary и Stream вызовов
│       ├── http/           # HTTP-движки, роутеры Chi и конвейеры декомпрессии трафика
│       │   └── middleware/ # REST Middleware для логирования, восстановления и трейсинга
│       └── worker/         # Abstract asynchronous background process runners
└── utils/                  # Низкоуровневые системные утилиты ядра рантайма Go
```

## 🧩 Границы архитектурных слоев

1. **Domain:** Полностью изолирован. Не импортирует сторонние библиотеки или пакеты фреймворка. Содержит структуры данных, бизнес-инварианты и интерфейсы репозиториев BLL-абстракций.
2. **Usecase:** Контур реализации бизнес-сценариев. Строго следует принципу *Single Responsibility*. Зависит исключительно от абстракций Domain.
3. **Repository (Слой адаптеров):** Физическое воплощение интерфейсов данных Domain. Управляет сырым SQL, контекстными транзакциями, пулами Redis или внешними клиентами сторонних микросервисов.
4. **Transport (Слой доставки):** Граничные сетевые контроллеры. Транслируют сетевые пакеты (JSON-потоки, Protobuf-бинарники) в чистые структуры данных, понятные слою Usecase.
5. **App:** Граница Dependency Injection. Собирает, связывает зависимости и склеивает все слои воедино на этапе стартапа.
6. **Pkg:** Обособленный, оптимизированный по памяти набор хелперов, утилит, который может быть бесшовно перенесен в любой другой облачный сервис.

## 🚀 Реализованные возможности в Example Service

* **Контекстный менеджер транзакций:** Потокобезопасное распределение ACID-трансляций через блоки выполнения UseCase между несколькими репозиториями.
* **Generic CRUD Репозиторий:** Базовый универсальный слой, минимизирующий написание шаблонного кода при сохранении полной поддержки контекстных транзакций.
* **Декораторы телеметрии:** Неинвазивный слой мониторинга, оборачивающий инстансы репозиториев механизмами трейсинга и сбора Prometheus через паттерн *Декоратор*.
* **Оборонительный HTTP-конвейер:** Масштабируемый Chi-роутер, вооруженный декодерами потоков Gzip/Brotli, структурированным логированием, сбором метрик и трекингом Exemplars.
* **Enterprise gRPC Раннер:** Тонко настроенное gRPC-ядро с политиками KeepAlive, Unary/Stream трейсингом и интерцепторами метрик «из коробки».
* **Конфигурация приложения:** Быстрое и безопасное чтение параметров окружения с помощью библиотеки Viper.

## 📈 Цепочка и последовательность вызовов запроса

Трафик запроса каскадно спускается вниз через развязанные интерфейсы, сохраняя чистоту границ:

```text
[Запрос Клиента] ──> Transport ──> Façade (DTO/Mapper) ──> Use Case ──> Repository ──> [СУБД/Брокер]
```
Обратный путь зеркально повторяет эту цепочку: мапперы переводят внутренние доменные модели обратно в транспортные DTO.
